# NC Global Assets — Next.js SSG Version

**Work in Progress:** Migration from React SPA (Vite) to Next.js 16 with Static Site Generation (SSG).

## Purpose

This version pre-renders all pages and blog posts as static HTML at build time, making content fully visible to Google Search Console and organic search. Solves the SPA indexing problem (46/100 SEO score) by converting to SSG (target: 72+/100).

## Stack

- **Framework:** Next.js 16 (app router)
- **Language:** TypeScript
- **Rendering:** Static Generation (SSG) with `output: 'export'`
- **Deployment:** Vercel
- **CMS:** SF-CMS (fetch-cms-content.mjs build script)

## Build & Deploy

```bash
# Development
npm run dev      # http://localhost:3000

# Production
npm run build    # Fetches CMS content + generates static HTML
npm start

# Vercel
vercel --prod
```

```
├── pages.json            # CMS pages
└── settings.json         # GA4 ID, etc.
```

## Workflow

### Build Process
1. `npm run build` → `fetch-cms-content.mjs` syncs posts/pages from SF-CMS to `src/content/`
2. Next.js builds → `generateStaticParams()` pre-renders `/blog/[slug]` for all posts
3. Output: `out/` directory with static HTML files (no JS execution needed for initial load)
4. Vercel deploys `out/` to production CDN

### Adding a Blog Post
1. Publish post in SF-CMS
2. Run `npm run build` → fetches new post
3. Deploy `npm run build && vercel --prod`

## Environment Variables

Required in Vercel (or `.env.local` for local dev):
- `CMS_API_URL` — SF-CMS public API endpoint
- `CMS_API_KEY` — SF-CMS API key

Set these in Vercel project settings under "Environment Variables".
